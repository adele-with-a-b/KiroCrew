The ssh self-target floor keeps the DNS self-check on by default and turns it off only for a wildcard that _file_operand_indices proves is a plain operand of git running a file subcommand (git add/rm/mv/diff/commit and the like). git must be the command's own program word and the subcommand the lowercase word right after it, read in the original case, so a wrapper misparse, a git global option value, a mixed-case alias, or a substitution body re-read from lowered text cannot turn the check off. The operand scan also stops at the first word with a glued separator (;|&), so a command bash runs after the separator keeps its DNS check. Programs whose every argument is a path (cp, ls, cat …) are already read by the data-consumer exemption, and tar is left out of both on purpose because tar -I / --rsh-command runs its argument. The lines are that git-only detector, its subcommand table, and the walk's file-operand flag with its two operand-check wirings.
